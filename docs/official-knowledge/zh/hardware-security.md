一、产品安全概述
RM-01 将网络接入控制、存储加密、设备绑定和物理防拆保护融入整机设计，保护交付的软件环境，限制
未经授权的访问、转移和使用。
整机安全设计围绕以下几个方面展开：
• 网络接入边界明确：通过 C1 连接设备，不会因此自动向整个办公网络开放内部服务。
• 软件环境与机器绑定：存储卡采用加密保护与“一卡一机”机制，限制交付环境被直接转移至其
他机器使用。
• 计算模块与原主板绑定：AGX、LPMU 均受到系统启动层面的绑定保护，限制未经授权的模块移
植。
• 结构外壳具备防拆保护：专用螺丝提高拆装难度，拆壳导致的 RTC 供电中断会使设备无法启动。
• 设备身份统一管理：TianshanOS 提供密钥、证书和连接身份管理功能，为设备管理提供认证支
持。
本说明介绍 RM-01 的硬件及配套嵌入式系统安全措施，与软件供应商提供的应用安全说明共同构成交付方
案。业务账号、应用权限和业务数据管理等内容，由软件安全文档说明。

三、网络接入与接口控制
3.1 C1 内部网络接入
C1 用于连接电脑、平板、手机等终端。连接后，终端会识别出一个 USB 网络接口，并加入 RM-01 内部子
网络，访问其中已开放的应用和管理服务。
C1 的接入方式是将终端接入 RM-01 内网，而非将 RM-01 自动接入终端原有的办公局域网。
例如，电脑通过 Wi-Fi 连接办公网络，同时通过 C1 连接 RM-01。在没有开启桥接、转发或其他对外接入路
径的情况下，办公网络中的其他设备不会仅因 C1 接通，就自动获得访问 RM-01 的通道。
这一设计便于本地直连使用，也减少了内部服务在不知情的情况下向办公网络开放的机会。
C1 是进入 RM-01 内部网络的有效入口，应连接可信、受管理的终端。网络共享、桥接、代理或端口转发
会改变原有访问范围，应由管理员统一配置。
技术注释｜子网络与接入边界
子网络是具有独立地址范围的一组网络设备。一台电脑可以同时连接办公网络和 RM-01 子网络，但两个网络是否互通
，取决于是否存在桥接、路由或其他转发通道。
C1 的网络关系不代表数据只能单向传输，也不等同于完全断网的物理隔离。其保护作用在于保持明确的接入路径，避
免因简单连接而自动扩大服务开放范围。

3.2 C3 连接目标控制
C3 是机身顶部的共享 USB 接口，可通过 TianshanOS 切换至 ESP32、AGX 或 LPMU。
不需要通过 C3 直连计算模块时，可将连接目标设置为 ESP32，使 C3 不再直接连接 AGX 或 LPMU。
ESP32 不提供 SSH 服务器登录入口，可减少该接口上不需要的计算模块直连路径。
接口切换仅改变 C3 的连接目标，不影响 C1 已有的网络连接，也不会自动关闭其他网络路径上的服务。
技术注释｜USB 切换与管理通道
C3 通过机内硬件多路选择器切换连接对象，同一接口在同一时刻连接所选模块。
SSH 是通过网络登录设备、执行命令的加密通信协议。串口是另一类管理通道，常用于设备配置、日志查看和维护。
C3 切换至 ESP32 后仍可能用于串口管理，因此“无 SSH 登录入口”不等于接口完全关闭。
3.3 按需开放局域网访问
需要在局域网中共享 RM-01 服务时，可将 C3 切换至 LPMU，通过以太网适配器连接交换机或路由器，并
由 TianshanOS 发起配套网络配置。
这属于主动扩展访问范围的部署方式。管理员应根据业务需要确定开放的服务、访问设备和连接路径，避免
将不需要的管理入口一并开放。
技术注释｜路由与端口转发
路由用于连接不同网络。端口转发用于将一个网络入口收到的连接交给内部服务。
配置端口转发后，对应内部服务的可访问范围会扩大。因此，局域网共享应作为独立的部署配置管理，不能沿用“仅
本机通过 C1 直连”时的访问边界。

四、存储加密与软件环境保护
4.1 加密保护与一卡一机绑定
RM-01 使用 CFexpress Type B 卡承载 AGX 的 Ubuntu Server、推理引擎及供应商软件的交付内容。上述
内容纳入加密保护范围，存储卡同时与指定 RM-01 建立“一卡一机”的绑定关系。
属于 A 机器的存储卡，插入 B 机器后无法运行原有交付环境。
这一机制限制了通过直接转移存储卡复用整套系统和软件的行为，保护软件供应商的授权权益，并保持交付
环境与指定机器的对应关系。
存储卡可以被读卡器识别和读取，但读取卡内内容不会解除设备绑定，也不意味着能够在另一台机器上运行
原有系统和软件。
技术注释｜加密与运行绑定
加密用于保护内容；设备绑定用于限定内容可以在哪台设备上运行。二者共同保护交付环境，但作用不同。
“一卡一机”描述运行限制，不表示读卡器无法读取整张卡，也不代表卡内所有分区和文件均不可读取。
4.2 应用交付与运行存储分离
供应商软件通过 CFexpress Type B 卡交付，在运行时自动迁入 LPMU 独立存储，迁移完成后从卡中移除。
此后，业务应用由 LPMU 承载运行。
这一流程将软件交付介质与实际运行存储分开，减少供应商软件长期留存在可拆卸卡中的暴露机会。迁移完
成后，取出 CFexpress Type B 卡，并不等于取得 LPMU 中的应用运行环境。
技术注释｜迁移后的文件处理
“从卡中移除”说明软件存放位置发生变化，不等同于执行不可恢复的安全擦除。
文件移除、加密和安全擦除是不同机制。LPMU 独立存储中的应用及数据保护，应结合软件安全方案和实际交付配置
说明。
4.3 推理计算与业务记录分工
AGX 推理引擎负责接收计算请求并返回结果。在本交付方案中，CFexpress Type B 卡不作为业务请求和推
理结果的持久化业务存储。
读取卡内的操作系统或推理引擎文件，不等于取得历史业务记录，也不等于取得 LPMU 中的应用数据。
会话、文件和业务结果是否保存、保存位置及访问权限，由供应商的应用配置和软件安全方案明确。
技术注释｜持久化与临时计算数据
持久化是将数据写入存储介质，使其在程序退出或设备断电后仍然保留。
模型文件、临时计算数据、运行日志和业务记录属于不同类别。“推理服务不保存业务记录”不应扩展为对所有模型
文件、缓存或日志的清除承诺。

五、计算模块防移植保护
5.1 AGX 启动绑定
AGX 采用专属设备 ID 和专属 BIOS 配置，并与原配主板绑定。
未经授权将 AGX 转移至其他主板，包括另一台 RM-01 的同型号主板，均无法启动系统。即使接口和主板
型号相同，也不能通过简单移植恢复原有推理环境。
5.2 LPMU 启动绑定
LPMU 采用专属 BIOS 配置，并与原配主板绑定。
将 LPMU 转移至其他开发板或另一台 RM-01 的同型号主板后，系统无法启动。这一措施限制了通过移植整
个应用计算模块，在其他主板上继续运行原有应用环境的行为。
AGX 和 LPMU 的绑定保护均作用于系统启动阶段，保护范围覆盖计算环境的启动，而不局限于单个应用的
授权检查。
技术注释｜设备身份与启动固件
设备 ID 用于区分设备身份。BIOS 是负责硬件初始化和系统启动的底层固件，本文沿用产品对专属启动固件的称呼。
接口兼容只表示具备物理连接条件，不代表满足设备的启动条件。模块绑定限制的是系统启动与跨主板使用，不能据
此推断所有存储介质都无法被单独读取。

六、物理防拆与启动保护
6.1 专用结构防护
RM-01 结构外壳采用两颗独家定制的特殊螺丝固定。特殊结构提高了拆装难度，增加了未经授权接触内部
主板和计算模块的门槛。
专用螺丝与内部启动保护共同构成机身防护：前者限制接触内部硬件，后者限制设备在结构外壳被拆开后继
续运行。
6.2 拆壳触发启动保护
RM-01 的结构设计将外壳拆卸与主板 RTC 备用供电关联。拆开结构外壳会导致 RTC 电池供电中断，触发硬
件层面的保护，使主板无法运行、整机无法启动。
这一设计限制了设备在未经授权拆解后继续使用，保护原有硬件装配和运行环境。
触发保护后，可由厂家进行恢复处理。内部检修和相关恢复应纳入厂家维护流程。
技术注释｜RTC 与启动保护
RTC 是 Real-Time Clock，即实时时钟。RTC 电池用于在主电源关闭后，为时钟等相关电路提供备用供电。
RM-01 将该备用供电状态与专用启动保护设计关联。供电中断后的启动限制属于 RM-01 的产品设计，不是所有计算机
都具备的通用特性。
此处“拆壳”指拆卸结构外壳，不包括按使用说明打开用于访问 C3 的顶部磁吸盖板。触发启动保护也不等于自动擦
除业务数据。
6.3 长期备用供电与厂家恢复
RM-01 选用高品质 RTC 电池，并采用低功耗备用供电设计，可满足至少五年的 RTC 供电需求，降低电池自
然耗尽对正常使用的影响。
RTC 电池自然耗尽同样会触发启动保护。因此，电池维护与拆壳检修均应由厂家统筹处理，避免自行断开
备用供电。
启动保护并非设备永久报废。厂家具备相应恢复能力，可在检修过程中处理电池及启动恢复问题。

七、TianshanOS 设备身份与凭据管理
TianshanOS 运行在 ESP32 上，提供密钥、证书和连接身份管理功能，支持对设备管理连接进行身份确认
，并管理相应认证凭据。
7.1 公私钥生成与管理
TianshanOS 支持在设备端生成 RSA、椭圆曲线等类型的公私钥对，并按用途进行管理。密钥可用于设备连
接认证，减少日常管理中对反复输入密码的依赖。
密钥默认设置为不允许通过导出功能导出私钥；只有创建时明确设置为允许导出的密钥，才可按对应设置导
出。
技术注释｜公钥与私钥
公钥提供给验证身份的一方，私钥由持有者保管。认证过程中，持有者使用私钥完成密码学操作，对方通过公钥验证
，无需取得私钥。
“默认不允许导出”是密钥管理策略，不等同于对所有物理攻击条件下的私钥不可提取作出承诺。
7.2 公钥授权与撤销
TianshanOS 支持将公钥部署到目标服务器，用于 SSH 密钥认证，并支持撤销已部署的公钥。
当某项管理连接停用或授权关系发生变化时，可移除对应公钥，终止该密钥的后续登录授权。
技术注释｜授权撤销范围
撤销公钥针对该公钥对应的认证权限，不会自动删除目标服务器上的其他账号、密码或公钥授权。完整的权限调整应
与账号管理同步进行。

7.3 连接身份核验
TianshanOS 支持记录和核验 SSH 主机指纹。已记录主机的指纹发生变化时，系统默认拒绝继续连接，需要
明确接受变更。
这一机制能够提示连接对象的身份变化，帮助管理员识别设备替换、系统重装或连接被冒用等情况，避免仅
凭网络地址判断设备身份。
技术注释｜主机指纹
主机指纹是服务器公钥的摘要，用于比较当前连接对象与此前记录是否一致。
首次连接时需要建立可信记录；后续指纹变化则需要核实原因。指纹变化不一定意味着攻击，但不应在未经核实的情
况下直接接受。
7.4 设备证书管理
TianshanOS 支持生成设备密钥和证书签名请求，向证书服务申请证书，并安装和管理设备证书及 CA 证书
链，为基于证书的身份认证提供支持。
技术注释｜数字证书与 CA
数字证书将设备身份与公钥关联，由证书机构 CA 签发。证书签名请求用于提交公钥及身份信息，无需提交私钥。
证书认证的实际生效范围取决于具体服务配置，证书管理功能本身不表示所有接口均已启用证书认证。
