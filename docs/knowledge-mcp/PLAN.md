# RM-01 官方知识 MCP 开发方案

> 方案阶段历史记录：现已进入本地实现阶段，当前状态与证据见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。部署与官网接入尚未执行。
日期：2026-10-30。状态：方案草案，待审阅；未开发、未部署、未验证客户端兼容性。

## 1. 目标与本轮范围

用户把官网提供的一段文字发给自己的 Agent。Agent 读取官方接入说明，识别客户端及版本，完成其支持的 MCP 配置与加载，实际搜索并读取一段官方资料，再开始回答关于 RM-01、TianshanOS、企业公开信息和样机申请的问题。

服务只提供官方资料检索和读取。理解问题、组织答案及语言转换由用户自己的 Agent 完成。只维护中文、英文资料，不依赖服务端模型或模型密钥。

本轮交付这份方案和已有资料副本。方案提出的代码、测试、网站入口和部署安排均属于后续工作，不代表已获执行授权。不会因编写方案而提交、推送、发 PR、合并、创建云资源或部署。

## 2. 已确认的边界

- 全部公开知识范围沿用[资料目录](../official-knowledge/README.md)，中文、英文各 44 个条目；其中两份 OCR 参考禁止直接作答。
- Admin/Root 指南依据 0.6.3；安全页面指南依据 0.6.1。网络配置、硬件安全为 Owner 确认的不随软件版本变更的通用资料。
- 官网只提供可复制文本框，不做客户端选择按钮、一键安装按钮或 Markdown 下载入口。
- 不提供账号登录、样机申请提交、库存查询、设备控制、合同签署、文件上传或私有案例访问工具。
- 不新增企业信息、客户身份、产品售价、性能结果或服务承诺。服务不能控制第三方 Agent 的最终表达，但应在每次返回中保留资料性质和限制，并用验收用例核对其是否被正确理解。

## 3. 技术决策及原因

| 决策 | 原因 |
| --- | --- |
| 一个独立 Cloudflare Worker，TypeScript | MCP 是独立服务，避免接入现有官网 Worker 的账号、样机、数据库和权限逻辑；TypeScript 与官方 MCP/Workers 工具链直接衔接 |
| 官方 SDK 处理协议，应用只实现检索和读取 | 不自行实现 JSON-RPC、版本协商或传输兼容层 |
| Streamable HTTP；无应用会话 | 搜索与读取不需要跨请求业务状态；保留旧版 Streamable HTTP 兼容通道，但不自行补建旧 SSE 服务 |
| 构建期切分与索引，运行时执行查询 | 不在每次调用中解析全量 Markdown 或重新分词；减少 CPU 消耗与结果漂移 |
| 初版用中英文全文索引 | 当前资料规模小，先验证实际检索效果，再根据漏检决定是否需要向量检索 |
| 资料和索引随 Worker 版本打包 | 同一发布中的内容、索引、来源清单保持一致；无需引入数据库和更新同步问题 |
| 初版不使用 D1、KV、R2、Vectorize、Workers AI、Durable Objects | 本需求没有持久会话、用户数据或模型调用；先消除不需要的成本和运维对象 |
| 公开匿名只读，限制输入与返回量 | 公开知识不需要用户账号；可滥用的读取量仍需边界，超限明确返回错误 |

MCP Handler 拟使用 Cloudflare 当前官方推荐的 `createMcpHandler`。官方说明其为逐请求无状态处理，且支持部分旧客户端请求；这不等于目标客户端已可用。协议与依赖选择必须通过第 8 节兼容性门槛后才能冻结。[S1][S2]

### 数据经过哪些步骤

```text
已审阅中英 Markdown + 来源清单
            ↓ 本地构建与内容检查
章节正文包 + 全文倒排索引 + 发布清单
            ↓ 同一版本部署
Cloudflare Worker /mcp
            ↓ 搜索结果 / 章节原文 / 来源 / 版本限制
用户自己的 Agent → 组织答案、翻译、引用
```

章节正文包为 Worker 模块内的数据，不绑定为可浏览的静态 Markdown 目录。不将整个仓库或内部说明文件上传到公开静态目录。服务返回可用原文不等于向普通用户提供下载产品。

## 4. 资料如何进入服务

### 4.1 先收敛可作答语料

现有 88 个条目是资料库存，不等于 88 篇都应按同等权重加入搜索。

| 资料性质 | 初版处理 |
| --- | --- |
| 对应版本指南、通用网络/硬件安全资料 | 正常索引；返回适用版本和安全限制 |
| 当前官网产品、模型、案例、企业联系、申请说明 | 正常索引；保留发布表述，不标为独立测试或实际成交承诺 |
| 历史企业介绍 | 默认不参与当前事实搜索；显式查询历史时纳入，标明日期并给出当前相关资料 |
| 低置信 OCR | 构建时排除；搜索和按 ID 读取都不能绕过排除策略 |
| 首页全量文案补充与页面重复内容 | 按实际重复段落去重；其中独有的状态/说明仍保留，不能整篇删除造成漏文 |
| 成功、失败、等待等界面文案 | 保留其触发状态；不把“申请已提交”当成当前用户已经完成申请 |
| 完整协议与企业主体中只有中文的部分 | 保留中文官方原文；英文检索应能找到中文依据及英文说明，不伪造官方英文合同 |
| README、INDEX、validation、方案与提取审计说明 | 仅作为维护材料，不作为企业事实索引 |

构建采用明确的条目与类型准入表，不递归发布目录中的所有 Markdown。排除条目不进入运行包，不能仅靠搜索排序隐藏。构建报告逐条记录“纳入、去重、参考、排除”及原因，防止静默少收资料。

### 4.2 切分与溯源

- 以标题、操作步骤、表格及提示块为单位切分。禁止拆掉前置条件、安全限制或表格标题，只留下看似可执行的步骤。
- 每段目标为 1–3 KB；上限先设 8 KiB UTF-8 正文，超长内容按段落或表格行分段，重复必要表头与上下文。操作前置条件单独存在时，通过相关章节引用带回，不无限复制全文。
- 长文章和 PDF 不能一次返回全篇。原始文档 ID、语言、稳定章节 ID 和原页号共同定位资料；标题重复时用确定的序号消歧，不能用正文哈希充当长期 ID。
- `content_hash` 表示内容，`corpus_revision` 表示整套资料发布版本。原文修改不静默变成“同一个旧内容”。章节增删和 ID 变动在构建报告中列明。
- 每个结果保留：标题、语言、原文、官网链接、标题路径/原 PDF 页码、文档适用版本、来源日期、资料性质、内容哈希、语料版本。
- 当前元数据中的自由文本适用说明，应在构建时人工审阅后映射为版本、历史状态和证据类型等确定字段，不能由查询时的猜测决定。

### 4.3 来源选择

对应版本操作指南优先回答该版本的操作问题；当前产品页面优先回答当前公开配置；通用网络/硬件资料按通用适用性处理。历史资料不自动覆盖当前资料。

同一问题出现不同来源描述时，返回差异及其来源，不把冲突合成为新事实。对未经资料支持的版本返回“缺少该版本的明确依据”，不静默回落为最新版本操作。

OTA 发布、库存、价格等涉及实时状态的提问，初版只返回已知快照时间和官方核对入口，不宣称实时。初版没有任意 URL 抓取工具，也不在调用时自动访问业务接口。

## 5. 两个 MCP 工具

仅将两个只读工具作为客户端必需能力，不要求客户端支持 prompts、resources、sampling 或服务端反向请求。协议发现与工具列举由 SDK 处理。

### `search_knowledge`

输入：

| 字段 | 约束 |
| --- | --- |
| `query` | 非空问题/关键词，最多 300 个 Unicode 字符 |
| `language` | `auto`、`zh`、`en`；默认 `auto`，决定优先语言而不是禁止有依据的跨语回落 |
| `version` | 可选设备版本字符串；只匹配已登记版本，不自动改变文档版本 |
| `include_history` | 默认 `false`，显式查询历史时开启 |
| `limit` | 默认 5，最大 8 |

输出：匹配结果、每条不超过 400 字符的摘录、来源/适用信息、可供读取的 `section_id`、`corpus_revision`，以及是否使用了另一语言原文。工具成功但无匹配时返回空列表和明确的无结果说明，不生成答案、不随意推荐不相关页面。

检索方法：英文按词与词形做有限归一；中文采用字符二元组，保留完整型号、接口、缩写与数值标识。使用倒排索引和 BM25，给标题、型号与精确短语合理加权。空白、大小写和全半角按固定规则归一，不能改写技术数值。

只维护少量有来源的同义表达，如“样机/借用”“散热/风道”“管理员/admin”。不堆砌手写问答或将答案硬编码到关键词规则。纯型号查询时并搜中英，避免因语言猜测漏检。自然语言漏检通过固定问题集定位原因。

去重后再给出结果，避免中文、英文、首页数据补充占满同一个问题的前 5 条。安全版本与历史标记应由确定过滤规则执行，不能只靠一个排序分数。

### `read_section`

输入：`section_id`、搜索结果给出的 `corpus_revision`。

输出：完整的受限大小章节正文及与搜索相同的来源/适用元数据；附必要前置条件、安全说明和相关章节 ID。英文说明引用中文完整协议时，相关 ID 必须指向实际可读的中文内容。

ID 不存在、版本已变化、条目未开放均明确返回对应工具错误，不猜 ID、不读取任意磁盘路径、不接收任意 URL。语料更新后，旧版本读取应返回“资料已更新，请重新搜索”，而不是返回不同版本的正文。

两个工具均声明只读性质；实际实现中也不含业务写入路径。声明本身不能替代对路由和数据访问的检查。

建议硬边界：MCP HTTP 请求体最大 32 KiB，搜索结果/读取结果整体最大 32 KiB；正文上限与 JSON 元数据开销一起检查。超限返回明确错误，不静默截断。数值为方案初值，实施时以真实章节统计调整并记录原因。

## 6. 服务与官网接入

拟采用独立子域名 `mcp.rminte.com`，路径如下。域名为提案，尚未创建或绑定。

| 路径 | 作用 |
| --- | --- |
| `/mcp` | MCP Streamable HTTP 服务 |
| `/connect` | Agent 可直接读取的中英文接入说明 HTML，普通 HTTP 获取正文即可读，不依赖浏览器执行脚本 |
| `/health` | 最小健康信息：服务版本、语料版本；不显示环境变量、绑定、堆栈或用户查询 |
| 其他路径 | 明确 404；不暴露内部资料目录 |

官网联系/指南区域的具体放置位置沿用品牌规范，实施时做局部设计与桌面、手机、中英验证。页面只有一段可复制文本；不能变成客户端向导或新增下载入口。

拟定中文文本（地址待实际部署核实后替换）：

> 请读取 RMinte 官方接入说明 https://mcp.rminte.com/connect ，检查你当前使用的 Agent 客户端及版本，按该版本支持的方式接入 RMinte 官方只读知识 MCP。完成必要加载后，实际搜索“如何申请 RM-01 样机”，读取命中的官方章节，并展示来源以确认连接成功。如需要重启、升级或额外组件，请明确说明需要我完成的操作，不要报告尚未验证的成功。

`/connect` 必须让 Agent：确认具体客户端与版本 → 查对应官方配置方式 → 保留原配置并只增加本服务 → 完成必要重载 → 发现两个工具 → 搜索并读取正文 → 给出原始来源与语料版本。具体修改配置仍遵守用户客户端自身的许可规则。

不把“写入配置”当作“加载成功”，不把“工具能列出”当作“知识搜索成功”。需要重启的客户端明确等待重启；不支持远程 MCP 时说明限制及已核验替代方式，不自动安装未经核实的桥接包。

## 7. Cloudflare 部署与费用

初版只需要 Workers 计算和一个域名绑定。源码、章节、索引在构建时合成一个确定版本；不设置运行时写入绑定，不读取官网后台凭据。[S1]

官方当前列出的 Workers Free 限制为每日 100,000 次请求、每次 10 ms CPU、128 MB 内存；请求额度并非本服务独享，也不能把一次用户问答等同于一次请求。发现工具、搜索和读取会产生多次请求。[S3]

因此“可以先评估免费档”是方案，不是免费运行保证。实施中记录构建包大小、启动开销、冷热请求、搜索长查询/高频词及大章节返回的 CPU 与内存。普通本地运行时间不能证明 Cloudflare CPU 配额满足；云端指标只能在获得测试部署授权后取得。若超预算，先查索引加载、解析和查询根因，再决定付费方案，不直接追加数据库或模型服务。付费以账户当时价格和授权为准。[S4]

部署前提供确定提交/快照、构建报告、语料清单、客户端验证记录及回滚版本。授权后先部署 MCP，再核对正式地址的连接/检索/引用，最后才发布官网入口；入口不得先指向一个未验收的服务。

回滚以同一版本的代码、索引和语料整体回滚；不跨版本拼装。该 Worker 的发布不顺带发布 OTA、案例、样机或其他服务。

## 8. 客户端兼容性门槛

当前只列验证对象，不宣称支持。Pi、Hermes、OpenClaw、DeepSeek Harness 的名称、对应项目和版本均须由官方来源核对；尤其不能把 OpenClaw 写成 OpenCloud，也不能把同名项目当作目标客户端。

每个对象必须记录：官方项目地址、具体版本、原生远程 MCP 支持情况、协议/传输、配置位置与字段、是否依赖扩展、加载/重启方式、实际工具调用结果。安装桥接、修改真实客户端配置或发起付费模型请求均不因本方案而自动授权；可先用协议客户端做不调用模型的验证。

| 状态 | 对外如何表述 |
| --- | --- |
| 官方文档明确，当前版本实测完成 | 可写入接入说明，注明版本范围和加载方式 |
| 文档明确但未实测 | 标为待验证，不承诺自动接入 |
| 需要官方扩展或本地桥接 | 单列组件与安装要求；仅在核验、测试并获相应安装授权后提供步骤 |
| 名称/项目不明或无受支持路径 | 不提供猜测配置；说明未支持的原因和已验证替代客户端 |

Cloudflare 当前 Handler 对旧请求的兼容只是工具、资源等的部分通道：不保留会话，也不提供独立旧 SSE 端点。实施先对最旧的目标客户端运行发现、列工具、搜索、读取和重复请求；若不兼容，重新选择有官方依据的 SDK/服务实现，并更新本方案，不能编造“全客户端通用”。[S1][S2]

依赖版本在实施时核对并锁定配套的 `agents`、MCP SDK、`zod` 与 Wrangler；不把本方案日期或某篇示例中的依赖版本永久写死为兼容性结论。

## 9. 可验收的开发阶段

| 阶段 | 产物 | 退出标准 |
| --- | --- | --- |
| A：语料构建 | 准入表、切分器、索引、来源映射、差异报告 | 纳入/排除完整可解释，危险操作上下文和表格不丢失；相同输入产物一致 |
| B：本地只读 MCP | 两个工具、Worker 路由、本地协议验证 | 真实 MCP 客户端可搜索/读取；无结果、非法输入、版本变化和排除条目行为正确；不需要模型请求 |
| C：检索评估与兼容性 | 固定问题集、运行记录、客户端版本矩阵 | 满足下方内容验收；仅为已实际通过的客户端编写接入步骤 |
| D：授权测试部署 | 独立测试 Worker、Cloudflare CPU/错误指标 | 正式传输与来源可达，计算开销经云端证据验证；无真实设备或业务写入 |
| E：授权生产与官网入口 | 正式 MCP、接入说明、可复制文本框 | 正式地址完成发现→搜索→读取；官网中英/桌面/手机、复制与焦点通过；部署提交可对应、可回滚 |

“完成本地开发”“通过协议测试”“兼容某客户端”“完成云端测试”“正式上线”分别记录，不互相替代。本轮停留在方案交付。

### 内容验收

建立至少 36 道中英文配对问题（72 次检索），覆盖：产品/模型、硬件/散热、系统操作、网络、安全、12 个案例的识别、样机、企业联系、版本及无依据问题。先根据原文标定期望章节，再运行检索，不在看到结果后修改预期来过关。

- 所有有依据的问题，Top 5 应包含正确依据；跨语问题允许返回中文原文，但须明确语言回落。未达到时列出失败并修复，不以总体命中率隐藏关键漏检。
- 版本适用、危险操作限制、完整协议语言、实时状态、私有权限、宣传/示意/模拟边界这些关键用例必须全部满足，不得以一般检索成功抵消。
- 至少包括：“0.6.3 无卡时如何保存/恢复自动化”“安全指南是不是 0.6.3”“C1 是否会把 RM-01 接入办公网”“哪些接口只能断电插拔”“样机押金与运费”“申请是否等于获批”“英文完整借用合同”“当前全部配置是否都有 256GB”“现在最新固件是什么”“公开案例是否意味着可直接看演示”“公司注册资本多少”。
- 每个返回章节的来源、版本、语言与哈希必须对应构建清单；OCR 条目和任意 URL/路径不能通过读取工具取得。
- 重复资料不能挤满结果；长文读取不能静默截断表格或漏掉操作限制。未知问题明确无依据。

### 协议与部署验收

先验证新版发现流程及目标旧版协商流程、列工具、搜索、读取、重复请求、断开重连、错误参数与超限行为。按当前官方规范选择具体协议用例，不把旧版 `initialize` 与新版发现机制混成同一必需步骤。[S2][S5]

检查无 Origin 的合法非浏览器客户端；浏览器 Origin 按实际接入域名和 SDK 规则配置，不将 CORS 误当作鉴权。检查错误不泄漏堆栈或文件路径。对请求大小、并发压测和返回量设定可重复输入；不把内存计数器当成跨实例一致的限流。

正式运行的监控仅保留服务版本、语料版本、请求计数、耗时和错误类别，不在应用日志主动记录完整问题或原始请求体。Cloudflare 平台日志采集另行检查并明确其实际配置，不能宣称匿名服务没有任何平台访问日志。

## 10. 拟修改的位置

| 位置 | 后续职责 |
| --- | --- |
| `docs/official-knowledge/` | 人工可审阅的官方原文及来源清单 |
| `docs/knowledge-mcp/` | 方案、后续兼容性与验收记录 |
| `services/official-knowledge-mcp/` | 独立 Worker、语料构建、检索、协议适配和必要测试；本轮不创建服务代码 |
| 官网现有合适入口 | 只在服务部署与验收后增加复制文本框；路径和视觉方案实施时确定 |

内容更新由明确的来源更新触发构建，审阅变更、重新检查相关问题集后发布。初版不创建定时爬虫或自动发布任务。服务器无法靠“只读”自动保证资料常新，应始终返回采集/来源日期和语料版本。
